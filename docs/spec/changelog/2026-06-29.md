## Graph subsystem: construction, normalization & printing (2026-07-01)

Phase 1 makes `Graph[...]` a real value.

- **`Graph`** (`src/graph/construct.c`) — normalizes edge sugar
  (`Rule`/`->` → `DirectedEdge`, `TwoWayRule`/`<->` → `UndirectedEdge`; existing
  `DirectedEdge`/`UndirectedEdge` pass through), derives vertices in
  first-appearance order for `Graph[edges]`, validates, and returns the
  canonical `Graph[List, List]`. Malformed input (self-loops, parallel edges,
  3-arg edges, unknown endpoints) is left unevaluated; anti-parallel directed
  edges are allowed. Reaches a fixed point (returns `NULL` when already
  canonical).
- **`GraphQ`** (`src/graph/graphq.c`) — validity predicate over the shared
  `graph_is_valid` helper (`src/graph/graph_util.c`).
- **Parser** — added `<->` → `TwoWayRule[u, v]` (precedence 120, like `Rule`),
  matched ahead of `<>`/`<=`/`<`.
- **Printer** — `DirectedEdge`/`UndirectedEdge` print infix as `u -> v` /
  `u <-> v` (round-trippable); a graph shows the terse summary
  `Graph[<n vertices, m edges>]` in standard output, with `InputForm`/`FullForm`
  printing the literal constructor.
- Tests: `tests/test_graph.c` (edge-sugar normalization, vertex derivation,
  summary printing, `GraphQ` truth table, malformed-input rejection, InputForm
  round-trip). Both builtins carry `ATTR_PROTECTED` and docstrings.

## Graph subsystem: query / representation builtins (2026-07-01)

Phase 2 adds readers over the canonical form (all `ATTR_PROTECTED`, all with
docstrings, one builtin per file in `src/graph/`):
`VertexList`, `EdgeList`, `VertexCount`, `EdgeCount`, `AdjacencyList`
(`[g]` and `[g,v]`), `VertexDegree`/`VertexInDegree`/`VertexOutDegree`
(`[g]` and `[g,v]`), and `DirectedGraphQ`. Degree conventions: total degree
counts incident edges; a directed edge adds to source out-degree and target
in-degree, an undirected edge adds to both in- and out-degree of each endpoint.
Adjacency uses successors for directed edges. Tests extended in
`tests/test_graph.c` (directed cycle + undirected path).

## Graph subsystem: matrix views (2026-07-01)

Phase 3 bridges graphs to the dense-matrix world (all `ATTR_PROTECTED`, with
docstrings): `AdjacencyMatrix` (0/1, symmetric for undirected — a plain matrix
consumable by `Det`/`Tr`/`Eigenvalues`), `IncidenceMatrix` (`|V|x|E|`, oriented
for directed edges), and `AdjacencyGraph` (inverse: builds a graph on `1..n`
from a 0/1 matrix, undirected iff symmetric). `AdjacencyGraph[AdjacencyMatrix[g]]`
round-trips `g`'s edges. Tests cover the circulant matrix of a directed 4-cycle,
undirected symmetry, `Det`/`Tr` interop, and both round-trips.

## Graph subsystem: generators (2026-07-01)

Phase 4 adds standard constructors (`src/graph/generators.c`, all
`ATTR_PROTECTED`, with docstrings): `CompleteGraph[n]`, `CycleGraph[n]`,
`PathGraph[n]`/`PathGraph[{v...}]`, and `RandomGraph[{n,m}]`. Each assembles a
`Graph[...]` and lets the evaluator canonicalize/validate it. `RandomGraph`
samples `m` distinct edges via the seeded system RNG (evaluates `RandomSample`
over the candidate edges), so it honors `SeedRandom`; it returns unevaluated if
`m > n(n-1)/2`. Tests cover K5 counts/degrees, cycle/path structure, explicit-
vertex paths, and seeded determinism.

## Graph subsystem: search & computation algorithms (2026-07-01)

Phase 5 adds the algorithmic core over a shared integer-indexed adjacency
builder (`graph_build_adj`/`graph_adj_free` in `src/graph/graph_util.c`, with a
component-counting helper; documented `expr_hash` upgrade path). All
`ATTR_PROTECTED`, with docstrings:
- `FindShortestPath[g,s,t]` (BFS path; `{}` if unreachable) and
  `GraphDistance[g,s,t]` (length; `Infinity` if unreachable) — directed graphs
  follow edge direction, undirected are symmetric.
- `ConnectedComponents` / `WeaklyConnectedComponents` (underlying undirected)
  and `StronglyConnectedComponents` (iterative Tarjan over directed adjacency).
- `FindSpanningTree` (BFS spanning forest as a graph; `VertexCount-1` edges when
  connected, original edge directions preserved).
- `ConnectedGraphQ` and `VertexConnectivity` (exact brute-force minimum vertex
  cut; `n-1` for complete graphs, `0` if disconnected).
Tests cover directed vs undirected distances, unreachable targets, weak vs
strong components, spanning-tree edge counts, and known connectivity values
(path 1, cycle 2, K4 3, disconnected 0).

## Graph subsystem: visualization (2026-07-01)

Phase 6 adds `GraphPlot[g]` (`src/graph/graphplot.c`, `ATTR_PROTECTED`, with
docstring): it emits a `Graphics[...]` expression using the existing primitives
(`Line` per edge; `Disk` + `Text` per vertex) with a circular vertex layout, so
the existing renderer draws it with no renderer changes (window when
`USE_GRAPHICS=1`, text placeholder otherwise). Directed edges are plain lines in
the MVP (arrowheads and a force-directed layout are future hooks). Builds under
both `USE_GRAPHICS=0` and `=1` (no raylib dependency in the emitter). Tests
assert `Head` is `Graphics` and count one `Line` per edge and one `Disk` per
vertex for `CycleGraph`/`CompleteGraph`.

This completes the graph subsystem MVP (Phases 0–6): construction, queries,
matrix views, generators, algorithms, and visualization — 30 builtins across
`src/graph/`, all with attributes, docstrings, and tests in
`tests/test_graph.c`.

## Notebook renderer: node-link diagram support (2026-07-01)

Follow-up to Phase 6. The notebook's `Graphics`→Plotly serializer
(`src/graphics/graphics_json.c`) previously handled only `Line` and `Polygon`,
so `GraphPlot` output rendered as a bare line (vertex `Disk`s and `Text` labels
were silently dropped, with no equal-aspect layout). Added:
- `Disk`/`Point` → `mode:"markers"` scatter traces (vertices),
- `Text[label,{x,y}]` → Plotly annotations (labels),
- "diagram mode" (triggered when `Disk`/`Text` are present): a square canvas
  with hidden axes and `yaxis.scaleanchor:"x"` so a circular vertex layout stays
  circular,
- sub-1e-12 coordinate snapping so floating-point dust (e.g. `sin(pi)`) doesn't
  blow up an auto-ranged axis.
Function `Plot[]` output is unchanged (no `Disk`/`Text`, so it keeps the
standard axed layout). This is the renderer change the Phase 6 plan had
incorrectly assumed unnecessary — it verified the primitive assumption against
the Raylib backend (`render.c`) but not the notebook serializer.

## Graphs auto-render + layouts, styling & HighlightGraph (2026-07-02)

Turned graph visualization from a single circular `GraphPlot` into a styled,
multi-layout renderer, and made graphs draw themselves.

- **Auto-display.** A bare valid `Graph[...]` result now renders as a node-link
  diagram, the same way the REPL already auto-displays `Graphics`/`Plot`
  (`src/repl.c`, both the interactive and notebook/sidecar paths). `FullForm`/
  `InputForm` still print the constructor. Implemented via a reusable
  `graph_render()` / `graph_default_graphics()` in `src/graph/graphplot.c`.
- **Layouts** (`src/graph/layout.c`, new). `graph_compute_layout()` provides
  deterministic kernels — circular, Fruchterman–Reingold spring-electrical,
  spiral, linear, grid, random, star, radial (BFS shells), layered (BFS
  layers), and bipartite (BFS 2-coloring). The full Wolfram `GraphLayout` name
  list is accepted and mapped onto these; the energy-minimization and
  tree/partite families are approximated by the spring / radial-layered /
  bipartite kernels (documented in `builtins/graphs.md`).
- **GraphPlot options.** `GraphLayout`, `VertexStyle`, `EdgeStyle`,
  `VertexSize`, `VertexLabels` — colors accept named/`RGBColor`/`GrayLevel`.
  Styling is emitted as per-primitive `RGBColor` directives, so both the
  notebook Plotly serializer and the Raylib renderer honor it.
- **HighlightGraph** (`src/graph/highlight.c`, new). `HighlightGraph[g, parts]`
  emphasizes chosen vertices/edges (accent color, rest dimmed) and returns a
  `Graphics`; parts may be vertices, edges, or a vertex list treated as a path.
- **Renderer.** `src/graphics/graphics_json.c` now maps a `Disk` radius to the
  marker pixel size (default radius → the previous 22 px), so `VertexSize`
  shows up in the notebook.
- New symbols in `src/sym_names.{c,h}` (`HighlightGraph`, `GraphLayout`,
  `VertexStyle`, `EdgeStyle`, `VertexLabels`, `VertexSize`); registrations,

  gains Layouts and Styling/Highlighting notebooks; docs in
  `builtins/graphs.md`.

## Graphs: distinct kernels for the advanced embeddings (2026-07-02)

`GravityEmbedding`, `HighDimensionalEmbedding`, and `HyperbolicSpringEmbedding`
previously all aliased to the plain Fruchterman–Reingold spring kernel, so they
rendered identically. Each now has its own kernel in `src/graph/layout.c`:
- **Gravity** — FR plus a central gravity well (pull ∝ distance × (1+degree)),
  drawing hubs inward and compacting the layout.
- **HighDimensional** / **Spectral** — pivot-MDS: BFS distances to two far-apart
  pivots (double-sweep) used as the 2D coordinates, laying the graph out along
  its diameter.
- **HyperbolicSpring** / **Spherical** — the spring layout followed by a radial
  warp (`r → r^0.45`) crowding vertices toward a disk boundary.
All remain fully deterministic. Verified pairwise-distinct against
`SpringElectricalEmbedding` and `RadialEmbedding`; the gallery's Layouts
notebook now demos all five.

## BipartiteGraphQ (2026-07-02)

Added `BipartiteGraphQ[g]` (`src/graph/bipartiteq.c`) — `True` iff the underlying
undirected graph is 2-colorable (no odd cycle). Single-BFS 2-coloring over the
on-demand integer adjacency (`graph_build_adj`), `O(V+E)`; edge direction is
ignored, an edgeless graph is vacuously bipartite, and a non-graph argument
gives `False` (matching `GraphQ`). `ATTR_PROTECTED` + docstring; tests in
`tests/test_graph.c` (even/odd cycles, path, star, complete-bipartite,
directed, disconnected, edgeless, non-graph). First addition from the
"missing Wolfram graph functionality" sweep.

## Graph distance metrics (2026-07-02)

Added `VertexEccentricity`, `GraphDiameter`, `GraphRadius`, `GraphCenter`
(`src/graph/metrics.c`) — a cohesive family over one BFS-per-vertex helper
(`O(V·(V+E))`) on the shared integer adjacency. Eccentricity is the greatest
shortest-path distance from a vertex (`Infinity` if any vertex is unreachable —
possible per-vertex on directed graphs); diameter = max eccentricity, radius =
min finite eccentricity, center = vertices attaining the radius. Directed graphs
follow edge direction; disconnected graphs give `Infinity`/`{}`. All
`ATTR_PROTECTED` with docstrings; tests in `tests/test_graph.c` (path, cycle,
complete, disconnected, directed out-star, single vertex). Second addition from
the missing-Wolfram-graph-functionality sweep.

## AcyclicGraphQ + TopologicalSort (2026-07-02)

Added `AcyclicGraphQ[g]` and `TopologicalSort[g]` (`src/graph/acyclic.c`), both
on Kahn's algorithm over the shared integer adjacency (`O(V+E)`).
`TopologicalSort` returns a forward-pointing vertex order for a DAG, else
`$Failed` (undirected edges act as 2-cycles → `$Failed`), matching Wolfram's
directed-only semantics. `AcyclicGraphQ` is `True` iff there is no cycle: for an
all-directed graph, Kahn removes every vertex (DAG); for a graph with undirected
edges, the underlying undirected graph is a forest (`E = V − #components`).
`ATTR_PROTECTED` + docstrings; tests in `tests/test_graph.c` (DAG, directed
cycle, 2-cycle, undirected tree/forest/cycle, edgeless, non-graph). Third
addition from the missing-Wolfram-graph-functionality sweep.

## GraphComplement (2026-07-02)

Added `GraphComplement[g]` (`src/graph/complement.c`) — the graph on the same
vertices whose edges are exactly the non-edges of `g`, built from an `n x n`
membership matrix (`O(V^2)`, the natural cost of a dense complement). Undirected
graphs give an undirected complement (edgeless → complete `K_n`, complete →
edgeless), directed graphs stay directed (all ordered non-self pairs minus the
present edges), and applying it twice restores the original edge set. Returns
the canonical `Graph` value directly. `ATTR_PROTECTED` + docstring; tests in
`tests/test_graph.c` (path, edgeless↔complete, cycle, double-complement,
directed, validity, non-graph). Fourth addition from the missing-Wolfram-graph
sweep.

## KirchhoffMatrix (2026-07-02)

Added `KirchhoffMatrix[g]` (`src/graph/kirchhoff.c`) — the graph Laplacian
`L = D - A` (degree diagonal minus adjacency), an ordinary `List`-of-`List`s
matrix built from the shared adjacency (`O(V^2)`). Every row sums to 0. It is
the bridge to spectral graph theory via the existing dense linear algebra:
`Eigenvalues[KirchhoffMatrix[g]]` exposes the algebraic connectivity and the
zero-eigenvalue multiplicity (= #components), and any cofactor `Det` gives the
spanning-tree count (Matrix-Tree). `ATTR_PROTECTED` + docstring; tests in
`tests/test_graph.c` (exact P3/C3/K4 Laplacians, zero row sums, trace = 2|E|,
and eigenvalue interop). Fifth addition from the missing-Wolfram-graph sweep.

## EdgeConnectivity (2026-07-02)

Added `EdgeConnectivity[g]` (`src/graph/edgeconnectivity.c`) — the minimum number
of edges whose removal disconnects `g` (companion to `VertexConnectivity`). By
max-flow/min-cut, the minimum s-t edge cut is the max s-t flow with unit
capacities; global edge connectivity fixes one source over all targets
(undirected) or scans all ordered pairs (directed). Each flow is Edmonds-Karp
(BFS-augmenting). Returns 0 for a disconnected / not-strongly-connected graph.
`ATTR_PROTECTED` + docstring; tests in `tests/test_graph.c` (complete, cycle,
path, star, bridge, disconnected, directed cycle vs path, non-graph). Sixth
addition from the missing-Wolfram-graph sweep.

## LineGraph (2026-07-02)

Added `LineGraph[g]` (`src/graph/linegraph.c`) — the line graph whose vertices
are the edges of `g` (the edge expressions themselves) and whose edges join two
that share an endpoint; a directed graph gives a directed line graph joining
arcs head-to-tail (`b == c` for `a->b`, `c->d`). `O(E^2)` pairwise comparison,
returns the canonical `Graph` directly. `ATTR_PROTECTED` + docstring; tests in
`tests/test_graph.c` (P3, cycle → cycle, `L(K4)` = 6 vertices/12 edges, star →
K3, directed head-to-tail, vertices-are-edges). Seventh addition from the
missing-Wolfram-graph sweep.

## EulerianGraphQ (2026-07-02)

Added `EulerianGraphQ[g]` (`src/graph/eulerianq.c`) — `True` iff `g` has an
Eulerian cycle. Reduces to a degree condition plus connectivity on the nonzero-
degree vertices: undirected needs all even degrees; directed needs in-degree =
out-degree everywhere (where weak connectivity then implies strong, so the
shared undirected `graph_count_components` check suffices). Isolated vertices are
ignored and an edgeless graph is vacuously Eulerian. `O(V+E)`, `ATTR_PROTECTED`
+ docstring; tests in `tests/test_graph.c` (cycles, K3/K4/K5, figure-eight,
disjoint cycles, isolated vertex, directed cycle vs path, non-graph). Eighth
addition from the missing-Wolfram-graph sweep.

## StarGraph + WheelGraph generators (2026-07-02)

Added `StarGraph[n]` and `WheelGraph[n]` (`src/graph/generators.c`), reusing the
existing generator helpers. `StarGraph[n]` is the star `K_{1,n-1}` (center 1
joined to n-1 leaves); `WheelGraph[n]` is a rim cycle on `1..n-1` plus a hub
joined to all rim vertices (`2(n-1)` edges, `W_4 = K_4`, requires `n >= 4`).
`ATTR_PROTECTED` + docstrings; tests in `tests/test_graph.c` exercise counts,
degrees, and the new predicates (star bipartite, wheel not). Ninth addition from
the missing-Wolfram-graph sweep — the first new generators beyond
Complete/Cycle/Path/Random.

## CompleteGraph multipartite form (2026-07-02)

Extended `CompleteGraph` (`src/graph/generators.c`) to accept a list of part
sizes: `CompleteGraph[{n1,n2,...}]` builds the complete multipartite graph (edge
between every pair in different parts, none within a part). `CompleteGraph[{m,n}]`
is complete bipartite `K_{m,n}`; `CompleteGraph[{2,2,2}]` is the octahedron. The
integer form `CompleteGraph[n]` is unchanged. Tests in `tests/test_graph.c`
(counts, degrees, bipartite/non-bipartite cross-checks, integer form intact).
Tenth addition from the missing-Wolfram-graph sweep.

## GridGraph + HypercubeGraph generators (2026-07-02)

Added `GridGraph[{d1,d2,...}]` and `HypercubeGraph[k]` (`src/graph/generators.c`).
`GridGraph` builds the k-dimensional grid on a d1 x d2 x ... lattice via
mixed-radix vertex indexing (cells adjacent when they differ by 1 in one
coordinate; `GridGraph[{n}]` is a path). `HypercubeGraph[k]` builds the k-cube
Q_k: 2^k vertices adjacent when they differ in one bit (k-regular, bipartite,
Q_2 = C_4). Both guard against size blow-up. `ATTR_PROTECTED` + docstrings;
tests in `tests/test_graph.c` cross-check counts, degrees, bipartiteness, and
that the 2x2x2 grid equals Q_3. Eleventh addition from the missing-Wolfram-graph
sweep.

## ClosenessCentrality (2026-07-02)

Added `ClosenessCentrality[g]` (`src/graph/centrality.c`) — the list of closeness
centralities `c_i = (r_i-1)^2/((n-1) S_i)` (Wolfram's disconnected-safe form;
`(n-1)/S_i` when connected, 0 when isolated), from a BFS per vertex over the
shared adjacency (`O(V*(V+E))`, follows edge direction). Values are exact
rationals — each `num/den` is reduced by the evaluator, so a symmetric graph
yields clean fractions (every C4 vertex is `3/4`, a star's leaves `3/5`).
`ATTR_PROTECTED` + docstring; tests in `tests/test_graph.c` (complete, cycle,
path, star, disconnected, directed sink, non-graph). Twelfth addition from the
missing-Wolfram-graph sweep.

## TransitiveClosure (2026-07-02)

Added `TransitiveClosure[g]` (`src/graph/transitiveclosure.c`). For a directed
graph it adds `u->v` for every `v` reachable from `u` (a BFS per source over
out[], `O(V*(V+E))`, staying directed); for an undirected graph each connected
component becomes a clique (one component labeling, then all within-component
pairs). Returns the canonical `Graph`. `ATTR_PROTECTED` + docstring; tests in
`tests/test_graph.c` (directed chain/cycle, undirected path/cycle, disjoint
components, already-complete, non-graph). Thirteenth addition from the
missing-Wolfram-graph sweep.
